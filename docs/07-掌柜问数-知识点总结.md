# 掌柜问数 — 知识点总结

> 本项目是一个 **NL2SQL（自然语言转 SQL）智能体**：用户用中文问业务问题，系统检索元数据、生成并校验 SQL、执行后流式返回结果。
> 知识点横跨「LLM 应用工程」「检索增强（RAG）」「后端工程」「数据建模」「中间件运维」「前端」六大块。
> 配套阅读：《06-代码导读》（代码地图）、`docs/course/`（9 讲教学）。

---

## 一、LLM 应用 & Agent 编排（项目核心）

| 知识点 | 在本项目的体现 |
|--------|---------------|
| **LangGraph 状态图** | `StateGraph` 编排 12 个节点；`add_node` / `add_edge` / `add_conditional_edges` / `compile()` |
| **并行 fan-out / fan-in** | `extract_keywords` 后 3 路召回并行；`merge_retrieved_info` 汇聚；`filter_table`/`filter_metric` 二次并行 |
| **条件分支** | `validate_sql` 用 lambda 判 `error` 决定走 `execute_sql` 还是 `correct_sql` |
| **TypedDict 状态管理** | `DataAgentState`，节点返回 partial dict 自动合并到全局 state |
| **依赖注入（Runtime Context）** | 节点不 import 依赖，全从 `runtime.context[...]` 取——便于测试 / 替换 / 避免循环 import |
| **流式进度（stream_writer）** | 每个节点发 `{"type":"progress","step":...,"status":"running\|success\|error"}`；图以 `stream_mode="custom"` 消费 |
| **LangChain LCEL 链** | `prompt \| llm \| parser` 三段式管道 |
| **OutputParser 选型** | JSON 输出用 `JsonOutputParser`（召回/过滤节点），纯文本用 `StrOutputParser`（生成/修正 SQL） |
| **init_chat_model 统一接入** | `model_provider="openai"`，`temperature=0`（确定性输出），`base_url` 可指向任意 OpenAI 兼容端点 |
| **Prompt 工程** | 每个 `.prompt` 都有「角色设定 + 禁止事项 + 最小必要集合」约束，保证输出可解析、可控 |
| **LLM 自愈 / 纠错环** | `validate_sql`(EXPLAIN 试错，不抛异常) → `correct_sql`(带报错做最小修正) → 直接执行 |
| **统一 YAML 序列化入参** | 复杂嵌套结构 `yaml.dump(..., allow_unicode=True, sort_keys=False)` 喂 LLM，比 JSON 省 token、易读 |

## 二、RAG 检索增强 & 知识库构建

| 知识点 | 体现 |
|--------|------|
| **三路混合检索** | 向量召回(字段, Qdrant) + 向量召回(指标, Qdrant) + 全文召回(取值, ES) |
| **向量检索（Qdrant）** | 1024 维，COSINE 距离，`score_threshold=0.6`，top-5 |
| **全文检索（Elasticsearch + IK）** | `ik_max_word` 中文分词，倒排索引，匹配字段取值字面命中 |
| **Embedding 模型** | `BAAI/bge-large-zh-v1.5`，自托管 TEI 服务（离线，不联网） |
| **多表征索引** | 每个实体的 name / description / 每个 alias 各嵌入/索引一份 → 用户怎么叫都能召回 |
| **LLM 关键词扩展** | jieba 分词关键词 ∪ LLM 扩展近义词，再去检索（提升召回率） |
| **检索后处理（merge）** | 按 id 去重、补全指标依赖字段、强制补主外键、把命中取值挂到字段 examples |
| **召回 vs 过滤两阶段** | 先广召回（多源），再用 LLM 按「最小必要集合」裁剪，控制 SQL 上下文体积 |
| **知识库离线构建** | `build_meta_knowledge` 一次性写 MySQL meta + Qdrant collection + ES index |

## 三、后端工程（FastAPI 异步栈）

| 知识点 | 体现 |
|--------|------|
| **FastAPI** | 路由、`Depends` 依赖注入、`StreamingResponse` |
| **SSE 流式响应** | `media_type="text/event-stream"`，逐块 `data: {json}\n\n` 推送进度与结果 |
| **应用生命周期** | `lifespan` 启动时 init 5 个长连接客户端，关闭时 close 4 个 |
| **请求级 vs 全局资源分离** | 长连接（引擎/ES/Qdrant/embedding）全局单例；每请求新建 session / repository |
| **全异步 I/O** | `async/await` 贯穿；`asyncmy` / `AsyncQdrantClient` / `AsyncElasticsearch` / `aembed_query` |
| **中间件** | 给每请求注入 `request_id`（基于 `ContextVar`，便于日志追踪一次请求全链路） |
| **CORS** | 白名单仅放行前端 `localhost:5173` / `127.0.0.1:5173` |
| **SQLAlchemy 2.0 异步 ORM** | `create_async_engine`、`async_sessionmaker`、`pool_size=10` + `pool_pre_ping`、`expire_on_commit=False` |
| **分层架构** | `api → service → agent(nodes) → repository → client` 严格单向依赖 |
| **Repository / Mapper 模式** | ORM Model ↔ 领域 entity 双向转换（`to_entity` / `to_model`） |

## 四、数据建模 & 数据库

| 知识点 | 体现 |
|--------|------|
| **元数据 vs 数据分离** | `meta` 库（知识库：表/列/指标元信息）+ `dw` 库（真实数据仓库）双库，各有 client manager 与 repository |
| **数仓星型模型** | `dim_*` 维度表 + `fact_order` 事实表；主外键支撑 JOIN |
| **SQL 校验** | `EXPLAIN` 不执行就验证语法、表/字段存在性 |
| **配置驱动建模** | `meta_config.yaml` 是知识的「真相源」；`role`(dim/fact、pk/fk/dimension/measure) 与 `sync`(取值是否进 ES) 驱动下游行为 |
| **JSON 列** | `examples` / `alias` / `relevant_columns` 用 MySQL JSON 类型存储列表 |

## 七、前端（轻量）

Vue 3 + Vite + SSE 消费：通过流式接口实时渲染「进度事件」与「最终结果」，对应 `data: {type:progress/result/error}` 三类消息。

## 一句话提炼

> 这是一个**完整的、生产形态的 RAG + Agent 应用范本**：用 **LangGraph** 把「**关键词扩展 → 三路混合检索（向量+全文）→ 元数据补全 → LLM 过滤 → SQL 生成 → 校验自愈 → 执行**」串成可观测的流水线，配套 **FastAPI 异步 + SSE** 服务化、**双库 + 三检索存储** 的数据架构，以及 **Docker Compose + uv + 离线 Embedding** 的工程落地。

## 可迁移的设计套路（带走这几条）

1. **召回再过滤**：广撒网召回（多源、多表征）→ LLM 按最小必要裁剪，兼顾召回率与上下文成本。
2. **校验 + 自愈**：先 `EXPLAIN` 静态校验、错误不抛而入 state、条件边触发一次性 LLM 纠错。
3. **依赖注入解耦**：业务节点只依赖抽象 context，外部能力运行时注入——易测、易换后端。
4. **元数据与数据分离**：知识库（描述"有什么"）与数据仓库（"是什么"）分库，互不污染。
5. **多表征召回**：name/description/alias 各存一份，对抗用户表达多样性。
6. **全链路可观测**：每步 `stream_writer` 进度 + `request_id` 贯穿日志，问题可定位。

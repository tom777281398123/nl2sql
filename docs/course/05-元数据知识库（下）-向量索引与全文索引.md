## 四、原理精讲

### 4.1 两类检索：语义 vs 关键词

| | 向量检索（Qdrant） | 全文检索（ES） |
| --- | --- | --- |
| 原理 | 文本→向量，比余弦相似度 | 分词→倒排索引，比关键词匹配 |
| 擅长 | **语义相近**（“营收”≈“销售额”） | **精确/字面匹配**（取值“华东”） |
| 本项目用于 | 字段信息、指标信息的召回 | 字段**取值**的召回 |
| 失效场景 | 专有名词、精确值 | 同义词、语义改写 |

本项目的设计：
- **字段/指标** → 向量检索（用户用什么词都可能，需要语义匹配）。
- **取值** → 全文检索（“华东”就是“华东”，要精确匹配，且取值量大、不适合全部向量化）。

两者**互补**，覆盖不同的召回需求——这就是第 1 讲思考题的答案。

### 4.2 向量索引：Embedding + Qdrant

**Embedding**：把文本映射到 1024 维向量空间，语义相近的文本向量距离近。本项目用 `BAAI/bge-large-zh-v1.5`（中文向量模型），通过 TEI 服务提供（第 2 讲）。

**Qdrant 的数据模型**：
- `collection`：相当于“表”，建时要指定向量维度和距离度量。
- `point`：一条数据 = `id` + `vector`（向量）+ `payload`（原始数据，这里是 ColumnInfo）。

看 `backend/app/repositories/qdrant/column_qdrant_repository.py`：

```python
class ColumnQdrantRepository:
    collection_name = 'data-agent-column'

    async def ensure_collection(self):
        if not await self.client.collection_exists(self.collection_name):
            await self.client.create_collection(
                self.collection_name,
                vectors_config=VectorParams(size=app_config.qdrant.embedding_size,  # 1024
                                            distance=Distance.COSINE))               # 余弦相似度

    async def search(self, embedding, score_threshold=0.6, limit=5) -> list[ColumnInfo]:
        result = await self.client.query_points(self.collection_name, query=embedding,
                                                score_threshold=score_threshold, limit=limit)
        return [ColumnInfo(**point.payload) for point in result.points]
```

精读要点：
- `ensure_collection`：**幂等**——不存在才建，可反复调用。
- `Distance.COSINE` + `score_threshold=0.6`：只返回相似度 ≥ 0.6 的，过滤噪声。
- `limit=5`：每次召回 top-5，控制候选规模。
- payload 直接反序列化成 `ColumnInfo` entity（第 4 讲的“entity 可序列化”优势在此体现）。

### 4.3 “多入口”索引：name + description + alias

看 `MetaKnowledgeService._save_column_info_to_qdrant`（`backend/app/services/meta_knowledge_service.py`）：

```python
for column_info in column_infos:
    points.append({"id": uuid4(), "embedding_text": column_info.name,        "payload": column_info})
    points.append({"id": uuid4(), "embedding_text": column_info.description, "payload": column_info})
    for alia in column_info.alias:
        points.append({"id": uuid4(), "embedding_text": alia,                "payload": column_info})
# 批量向量化（每批 10 条）
for i in range(0, len(embedding_texts), 10):
    batch_embeddings = await self.embedding_client.aembed_documents(embedding_texts[i:i+10])
```

**关键设计**：同一个字段，用它的**名称、描述、每个别名**分别生成一个 point，但 payload 都指向同一个 `ColumnInfo`。这样无论用户说“大区”“区域”还是“地区名称”，都能命中同一个字段。**这是召回率的工程保障。**（指标索引 `_save_metric_info_to_qdrant` 同理。）

批量 embedding（每批 10 条）是为了效率，避免逐条请求 TEI。

### 4.4 全文索引：ES + IK 分词

看 `backend/app/repositories/es/value_es_repository.py`：

```python
class ValueESRepository:
    index_name = 'data-agent-value'
    index_mappings = {
        "dynamic": False,
        "properties": {
            "id":        {"type": "keyword"},
            "value":     {"type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_max_word"},
            "column_id": {"type": "keyword"}
        }
    }
    async def search(self, keyword, score_threshold=0.6, limit=5) -> list[ValueInfo]:
        result = await self.client.search(index=self.index_name,
                                          query={"match": {"value": keyword}},
                                          min_score=score_threshold, size=limit)
        return [ValueInfo(**hit['_source']) for hit in result['hits']['hits']]
```

精读要点：
- `value` 字段用 `ik_max_word` 分词器（中文最细粒度切分），`id`/`column_id` 用 `keyword`（不分词，精确匹配）。
- `match` 查询 + `min_score` 阈值，返回 top-5 命中取值。
- 取值通过 `column_id` 关联回字段——召回到取值“华东”，就知道它属于 `dim_region.region_name`。

哪些取值进 ES？由第 4 讲的 `sync` 字段控制，见 `_save_value_info_to_es`：
```python
column2sync = {f"{t.name}.{c.name}": c.sync for t in meta_config.tables for c in t.columns}
for column_info in column_infos:
    if column2sync[column_info.id]:          # 只同步 sync=true 的列
        values = await self.dw_mysql_repository.get_column_values(table, column, 100000)
        value_infos += [ValueInfo(id=f"{column_info.id}.{v}", value=v, column_id=column_info.id) for v in values]
await self.value_es_repository.index(value_infos)
```

### 4.5 构建总编排 `build()`

`MetaKnowledgeService.build()` 把全流程串起来：

```
加载配置(OmegaConf)
 ├─ 处理表信息
 │   ├─ 2.1 _save_tables_to_meta_db        → 写 meta 库（第4讲）
 │   ├─ 2.2 _save_column_info_to_qdrant     → 字段向量索引
 │   └─ 2.3 _save_value_info_to_es          → 取值全文索引
 └─ 处理指标信息
     ├─ 3.1 _save_metrics_to_meta_db        → 写 meta 库
     └─ 3.2 _save_metric_info_to_qdrant     → 指标向量索引
```

入口 `backend/app/scripts/build_meta_knowledge.py` 负责初始化所有客户端、解析命令行参数（`--conf`、`--clean`），并支持先 `clean()` 再 `build()`。

### 4.6 清空的副作用（重点警示）

`.env` 里 `SYS_ISCLEAN_CONFIG=true` 时，**每次**运行 build 脚本都会先 `clean()`：删 meta 四张表、删 Qdrant 两个 collection、删 ES 索引。`clean()` 里注意删除顺序——先删子表（`column_metric`）再删父表，遵守外键约束（见 `meta_knowledge_service.py` 的 `clean()`）。

> 上机时务必知道：反复跑 build-kb = 反复清空重建。生产环境要把 `SYS_ISCLEAN_CONFIG` 设为 false 做增量。

## 六、常见坑

- build 前必须确保 embedding 服务真正就绪（第 2 讲），否则向量化报连接错误。
- ES 的 `min_score`/Qdrant 的 `score_threshold` 调太高会召回为空，调太低会引入噪声——需要调参。
- 重跑 build-kb 会清空，别在“刚扩了知识库”后又误跑导致丢数据。

### 挑战级（指向课程设计 · 召回评测方向）
5. 构造一个**召回评测集**：写 15–20 条业务问题，人工标注每条“应该召回哪些字段/指标/取值”（金标准）。写一个评测脚本，跑当前召回逻辑，计算召回率（Recall@5）。基于结果提出 ≥2 条改进（如调阈值、加别名、改 embedding_text 组合方式），并量化改进前后的差异。这是第 9 讲“召回评测”大作业的核心。

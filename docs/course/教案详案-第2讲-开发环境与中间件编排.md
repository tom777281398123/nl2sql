# 教案详案 · 第 2 讲：开发环境与中间件编排

> 教师授课用逐段细案，配合 `02-开发环境与中间件编排.md`（学生教案）使用。
> 体例：⏱ 时间 / 🗣 讲稿 / ✍ 板书 / ❓ 提问 / 💻 上机 / ⚠ 预案。

---

## 一、本讲定位与教学法说明

- **性质**：第一节动手课。把第 1 讲那句 `./run.sh start` 背后的四个中间件彻底揭开。
- **核心矛盾**：学生会把“环境搭建”当成枯燥的运维步骤；要让他们明白——**环境本身就是架构的一部分**，每个中间件对应一块知识库能力。
- **必须钉死的认知**：
  1. **“容器 Running” ≠ “服务 Ready”**（healthcheck 的意义）。
  2. **embedding 离线加载**：`MODEL_ID` 用本地路径而非 repo-id，是本项目最大的环境坑。
- **教学法**：先用一张表把四个中间件“认全”，再讲 Makefile/compose 怎么编排，最后重点攻克 embedding 离线这个难点。**先认人、再看编排、后攻难点**。
- **总时长**：4 学时（理论约 80 分钟 + 上机约 100 分钟，上机偏重）。
- **课前准备**：教师务必提前 `make middleware` 预热（首次拉镜像 + 模型加载很慢）；确认 `2.资料` 的模型已就位。

### 段落 1 · 四个中间件“认全”（16 min）

⏱ 0:06–0:22

🗣 **讲稿**：用一张表把四个服务“点名”，每个都问一句“它在本项目干嘛”，把它和知识库挂钩。

✍ **板书（中间件表，副板）**：
```
服务         端口        本项目职责
MySQL        3306        meta(元数据) + dw(真实数仓) 两个库
ES           9200        字段"取值"全文索引(带IK中文分词)
Qdrant       6333/6334   字段/指标的"语义向量"索引
Embedding    8081        文本→1024维向量(bge-large-zh-v1.5)
```

🗣 **逐个点评**（每个 30 秒，挂回第 1 讲）：
- MySQL：“注意它装了**两个库**——meta 描述数据、dw 真实数据。一台 MySQL 两种角色。”
- ES：“只管一件事——字段‘取值’的全文检索。‘华东’这种精确词靠它。”
- Qdrant：“向量库。字段、指标的语义召回靠它。”
- Embedding：“它不存数据，是个‘翻译官’——把文本翻译成 1024 维向量，喂给 Qdrant。”

❓ **提问**：“为什么字段用 Qdrant、取值用 ES，不能都用一个？”（引导回忆第 1 讲思考题 3；告诉他们第 5 讲有对照实验，今天先记住分工。）

### 段落 2 · Makefile × docker-compose 协作（14 min）

⏱ 0:22–0:36

🗣 **讲稿**：打开 `Makefile`，看顶部那段变量：
```makefile
DOCKER_COMPOSE := PROJECT_ROOT=$(PROJECT_DIR) docker compose \
	-p storekeeper-nl2sql \
	-f docker/docker-compose-debug.yml \
	--env-file docker/.env.debug \
	--profile middleware
```
🗣 逐项解释（这是“为什么用 make 包一层”的答案）：
- `docker compose` 的完整命令很长、参数多，每次手敲易错 → 用 Makefile 封装成 `make middleware` 一句话。
- `-p`：项目名（容器前缀）；`-f`：编排文件；`--env-file`：注入账号密码；`--profile middleware`：只起带这个 profile 的服务。

🗣 **常用目标速览**（打开 Makefile 的 target 部分扫一遍）：
```
make middleware  起动并等待健康
make down        停
make ps / logs   看状态/日志
make clean       删容器和数据卷(但保留embedding模型缓存!)
```
❓ **提问（埋第 2 讲思考题 1）**：“`make clean` 为什么特意**保留** embedding 模型缓存？”（先抛出，段落 4 讲完离线后学生自然懂——模型 1.2G 还不好下，删了重建很痛。）

✍ **板书（副板）**：
```
Makefile = 把超长 docker compose 命令封装成 make 短命令
make middleware/down/ps/logs/clean
clean 保留embedding模型缓存 → 为什么? (段落4答)
```

### 段落 3 · healthcheck：Running ≠ Ready（12 min）

⏱ 0:36–0:48

> 本段钉死认知 1，是贯穿工程的重要观念。

🗣 **讲稿**：打开 `docker/docker-compose-debug.yml`，看 MySQL 的 healthcheck：
```yaml
healthcheck:
  test: ["CMD-SHELL", "mysqladmin ping ... --silent"]
  interval: 10s
  retries: 30
  start_period: 30s
```
🗣 **讲透“两个状态”**：
> “一个容器‘**Running**’只是说进程起来了；但服务可能还在初始化（MySQL 在建库、ES 在装插件），这时连它会失败。‘**Ready**’才是能对外服务。healthcheck 就是用来探测 Ready 的。”

🗣 `make middleware` 用了 `up -d --wait`：“`--wait` 会一直等到所有服务 healthcheck 通过才返回。所以你 `make middleware` 返回时，服务是真就绪了。”

❓ **提问（第 2 讲思考题 2）**：“`start_period` 和 `interval` 有啥区别？为什么 ES 的 `start_period` 比 MySQL 长？”
🗣答：“`start_period` 是‘宽限期’，期间检查失败不算数（避免启动慢被误判不健康）；`interval` 是检查间隔。ES 启动慢（JVM + 可能装 IK 插件），所以宽限期更长。”

✍ **板书（重点）**：
```
┌────────────────────────────────┐
│ 容器 Running ≠ 服务 Ready        │
│ healthcheck 探测的是 Ready       │
└────────────────────────────────┘
up -d --wait → 等全部健康才返回
start_period=宽限期(失败不计) | interval=检查间隔
```

### 段落 4 · embedding 离线加载（难点，22 min）

⏱ 0:48–1:10

> 本讲最重要的难点，钉死认知 2。这是本项目区别于“照搬教程”的真实工程经验。

🗣 **抛问题（先制造痛点）**：
> “TEI 这个 embedding 服务，默认要去 huggingface.co 下载模型。但在我们的网络环境——”现场演示或回放第一次启动时的日志：
> ```
> Download failed: ... huggingface.co ... (超时)
> ```
> “它会一遍遍超时重试，**永远起不来**。整个知识库都没法构建。这是本项目第一个真实的坑。”

🗣 **讲解法**：打开 `docker/docker-compose-debug.yml` 的 embedding 段：
```yaml
embedding:
  environment:
    MODEL_ID: /models/bge-large-zh-v1.5            # ← 本地路径,不是 BAAI/bge-large-zh-v1.5
  volumes:
    - ./models/bge-large-zh-v1.5:/models/bge-large-zh-v1.5   # ← 把本地模型挂进容器
    - ./data/embedding:/data
```
🗣 **三个关键点**：
1. **`MODEL_ID` 填本地路径**：TEI 看到这是个路径（不是 repo-id），就当本地模型加载，**不联网**。
2. **挂载模型目录**：模型文件（约 1.2G）来自 `2.资料/2.docker compose/embedding/bge-large-zh-v1.5`，拷到项目 `docker/models/` 下。
3. **candle 后端回退**（讲日志现象）：TEI cpu 镜像默认想用 ONNX 权重，本地只有 pytorch 权重。日志会先报：
   ```
   Could not start ORT backend: ... model.onnx does not exist
   Starting Bert model on Cpu        ← 自动回退到 candle,加载 pytorch_model.bin
   Warming up model
   ```
   “看到第一行别慌——它**不是错误，是正常回退**。看到 Warming up，就快好了。”

🗣 **回收段落 2 的提问**：“现在懂为什么 `make clean` 要保留模型缓存了吧？——这模型 1.2G、还不好下，删了重建很痛。”

✍ **板书（重点框起来）**：
```
┌──────────────────────────────────────────┐
│ embedding 离线: MODEL_ID 用"本地路径"       │
│ 而非 repo-id, 否则卡死在 HF 下载            │
└──────────────────────────────────────────┘
模型挂载: docker/models/bge-large-zh-v1.5 → 容器/models/...
日志: ORT(onnx)失败 → candle接管(pytorch) → warmup  [正常!]
```

⚠ **预案**：学生机房若模型没拷到位，embedding 必起不来。教师课前务必确认 `docker/models/bge-large-zh-v1.5/pytorch_model.bin` 存在（约 1.2G）。

### 段落 5 · IK 分词器 + 小结（10 min）

⏱ 1:10–1:20

🗣 **IK 分词器（3 min）**：打开 compose 的 elasticsearch `command` 段，指出它启动时自动安装 `analysis-ik`：
> “ES 默认不会切中文——‘掌柜问数’会被当成一个整体或按字切。装了 IK 才能切成‘掌柜/问/数’这种有意义的词。第 5 讲建取值索引时用的就是 `ik_max_word`。”

🗣 **小结三句**：
1. 四个中间件 = 知识库三索引 + 向量化能力的载体。
2. Running ≠ Ready，healthcheck + `--wait` 保证真就绪。
3. embedding 必须离线加载本地模型，否则卡死。

❓ 留作上机：“去日志里亲眼找到‘ORT 失败 → candle 接管’那三行。”

## 四、上机部分细案（90 min）

⏱ 1:30–3:00

### 💻 上机任务 1：从零起停（30 min）

**分步骤**：
1. 先停干净：`./run.sh stop`
2. 启动（讲清首次会拉镜像 + 加载模型，慢）：`./run.sh start`
   ⚠ 预案：首次慢，可让它后台跑，期间继续讲；或教师已预热，学生直接 `status`。
3. 看状态等全绿：`./run.sh status`
4. 首次需构建知识库（干净环境）：`./run.sh build-kb`
5. 浏览器 http://127.0.0.1:5173 问一句，确认能用。

### 💻 上机任务 2：逐项手动验证（35 min）

> 对照 `docs/02-掌柜问数-环境验证脚本.md` 逐条跑，理解“每个服务怎么自证就绪”。

```sh
# Embedding: 应返回 1024 维向量
curl -sS http://localhost:8081/embed -X POST -H "Content-Type: application/json" \
  -d '{"inputs":["测试"]}' | head -c 200
# ES: 集群健康 + 验证 IK 分词
curl -sS http://localhost:9200/_cluster/health?pretty
curl -sS -X POST "http://localhost:9200/_analyze" -H "Content-Type: application/json" \
  -d '{"analyzer":"ik_max_word","text":"尚硅谷掌柜问数"}'
# Qdrant
curl -sS http://localhost:6333/healthz
# MySQL
mysql -h 127.0.0.1 -P 3306 -u storekeeper -p'178121' --protocol=TCP -e "SHOW DATABASES;"
```
❓ 检查点：“IK 把‘尚硅谷掌柜问数’切成了哪些词？如果不装 IK 会切成什么？”

### 💻 上机任务 3：观察 embedding 离线加载日志（25 min）

```sh
docker logs storekeeper-embedding 2>&1 | grep -E "ORT backend|Bert model|Warming up"
```
让学生找到“ORT 失败 → candle 接管 → warmup”三行，对照段落 4，理解回退逻辑。

⚠ **进阶可选**：让胆大的学生临时把 `MODEL_ID` 改回 `BAAI/bge-large-zh-v1.5`、重启 embedding，亲眼看它卡在 HF 下载，再改回来——**痛过一次终身难忘**。

## 六、本讲常见问题预案

| 学生可能问 | 应对 |
| --- | --- |
| 3306 端口冲突 | `lsof -iTCP:3306` 找进程；停本机 MySQL 或改映射 |
| embedding 一直不健康 | 模型没挂载/没拷到位；查 `docker/models/...pytorch_model.bin` |
| ORT backend 报错是不是坏了 | 不是,正常回退到 candle,看后面有没有 Warming up |
| make middleware 卡在 Waiting | `make logs` 看哪个服务没过健康检查;ES 内存不足调 ES_JAVA_OPTS |
| clean 后查询报错 | 数据卷被清,重跑 build-kb |

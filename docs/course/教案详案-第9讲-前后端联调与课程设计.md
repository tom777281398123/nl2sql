# 教案详案 · 第 9 讲：前后端联调与课程设计大作业

> 教师授课用逐段细案，配合 `09-前后端联调与课程设计大作业.md`（学生教案）使用。
> 体例：⏱ 时间 / 🗣 讲稿 / ✍ 板书 / ❓ 提问 / 💻 上机 / ⚠ 预案。

---

## 一、本讲定位与教学法说明

- **性质**：收口 + 启动课程设计。前半段把全课串成完整链路、教会端到端 debug；后半段正式发动大作业。
- **核心矛盾**：前 8 讲是“分段拆解”，学生脑中知识点是散的；本讲要**把它们串成一条完整的、自己能讲清的链路**，并从“学会了”跨到“能创造”。
- **必须钉死的认知**：
  1. **全链路心智模型**——能从前端输入一路讲到结果返回，并说清每段“为什么”。
  2. **自底向上的端到端 debug 方法论**。
  3. **课程设计 = 一次真实小型工程**，重在“理解所改之处 + 讲清设计权衡”。
- **教学法**：用“一次查询的完整旅程”做总复习（串珠子），再用故障演练练 debug，最后发动大作业并讲清评分。**串联→实战→发动**。
- **总时长**：4 学时（理论/串讲约 50 分钟 + 联调与故障演练约 70 分钟 + 大作业发动与选题约 40 分钟，时间偏实践）。

### 段落 1 · 前端如何消费 SSE（12 min）

⏱ 0:05–0:17

🗣 **讲稿**：
- 前端在 `fronted/`（强调拼写：fronted 不是 frontend），Vue3 + Vite，跑 5173。
- “前端向 `/api/query` 发请求，按 SSE **逐条读 `data:{...}`**，根据第 8 讲那套 type 协议分别处理：”
  - `progress` → 更新进度条（让用户看到“正在召回字段…”）。
  - `result` → 拿 data 渲染成表格。
  - `error` → 弹错误提示。
- 回收第 8 讲：“你上节课用 curl 看到的那些 `data:` 行，前端做的就是把它们**翻译成界面**。这就是事件协议作为‘前后端解耦契约’的意义——前端根本不用懂智能体内部，只认这三种 type。”

🗣 引导：“等会上机，打开浏览器开发者工具的 Network 面板，能看到 `/api/query` 的 EventStream——和 curl 一样的内容，但前端把它画成了界面。”

✍ **板书（副板）**：
```
前端(fronted/, Vue, 5173): 读SSE data:{...}, 按type:
  progress→进度条  result→结果表  error→提示
事件协议 = 前后端解耦契约(前端不懂智能体内部)
```

### 段落 2 · 全链路总复习（串珠子，重点，22 min）

⏱ 0:17–0:39

> 本讲灵魂。把九讲串成一条线，让学生形成“系统级理解”。**边画边让学生补充“这步为什么”。**

🗣 **讲法**：以“统计各地区销售前三产品”为例，从前端一路讲到结果，**每经过一站，点名一个知识点和它的‘为什么’**。建议让学生接龙补充。

✍ **板书（全链路大图，逐步画出，保留到下课）**：
```
前端输入(第9)
 → POST /api/query (第8: 路由+Depends装配QueryService)
   → lifespan备好的长连接 + 每请求新session (第8/第3)
   → graph.astream + Context注入 (第8/第6)
     → extract_keywords: jieba (第6)
     → 并行召回: Qdrant向量(字段/指标)+ES全文(取值) (第6/第5)
         ← 知识库由build-kb预建 (第5/第4)
     → merge: 补主外键、并取值 (第6)
     → filter: LLM裁剪 (第6)
     → add_extra_context: 日期/方言 (第7)
     → generate_sql: LLM+prompt硬约束 (第7)
     → validate_sql: EXPLAIN→条件边 (第7)
         →(失败) correct_sql (第7)
     → execute_sql: dw执行,writer推result (第7)
   → service包 data:...\n\n SSE (第8)
 → 前端按type渲染 (第9)
地基: 配置/日志/异步/分层/DI (第3)
环境: 4中间件Compose编排,embedding离线 (第2)
为什么这么设计: 防幻觉/可控/省token (第1)
```

🗣 **串讲时反复回扣“三大设计动机”（第 1 讲那句话）**：
> “走完这一圈，回头看第 1 讲那句话——‘准确性靠喂对、喂准、喂少的工程’。**喂准**=知识库防幻觉(4、5)；**喂少**=召回+过滤(5、6)；**可控**=校验+纠错+prompt(7)。整个系统就是为这三件事服务的。”

❓ **接龙提问（边画边问，检验吸收）**：
- “并行召回那步，为什么能并行？”（各写各 state key，第 6）
- “merge 为什么补主外键？”（为了 JOIN，第 6）
- “validate 失败后怎么走？”（条件边读 error，第 7）
- “session 为什么每请求新建？”（事务态不能共享，第 3/8）

### 段落 3 · 端到端 debug 方法论（12 min）

⏱ 0:39–0:51

> 钉死认知 2。这是学生做大作业、将来工作都用得上的硬技能。

🗣 **讲稿**：“查询出问题时，别瞎猜，**自底向上逐层排除**。”

✍ **板书（debug 分层表，重点）**：
```
查询出错 → 自底向上排查:
 中间件   ./run.sh status (5项健康)
 知识库   三索引有数据吗(第5上机)
 智能体   python -m backend.app.agent.graph 看哪个节点报错
 API     curl -N 打接口看SSE
 前端     浏览器 Network/Console
 日志     按 request_id 串一次请求 (第3/第8)
```
🗣 讲方法论价值：
> “这套‘自底向上’的思路，本质是‘**先确认地基没问题，再往上找**’。中间件不通，上面全白搭；中间件好了再看知识库有没有数据……一层层缩小范围。这比对着代码干瞪眼高效得多。做大作业遇到问题，就按这张表走。”

## 四、上机部分细案

### 💻 上机任务 1：完整联调（35 min）

⏱ 课间后 0:00–0:35

**分步骤**：
1. `./run.sh start` → `./run.sh status` 全绿。
2. 浏览器 http://127.0.0.1:5173 ，依次问：
   - “统计一下各个地区销售排行前三的产品”
   - “各品牌的成交总额是多少”
   - “上个季度华东地区的订单数量”
3. 打开开发者工具 Network，找到 `/api/query`，看 EventStream（对照 curl）。
4. 观察进度条点亮顺序，对照段落 2 的全链路图。
❓ 检查点：“界面上的进度条，每一格对应后端哪个节点？”

### 💻 上机任务 2：故障演练（35 min，核心）

⏱ 0:35–1:10

> 用真实故障练 debug 方法论。教师可统一“制造”一个故障让全班排查，或让学生互相设障。

**演练方案（教师择一制造故障）**：
- 方案 A：停掉 embedding（`docker stop storekeeper-embedding`），让学生发现“召回失败”并定位到中间件层。
- 方案 B：清空 ES 取值索引（`curl -XDELETE localhost:9200/data-agent-value`），让查询召回不到取值，定位到知识库层（需 build-kb 恢复）。
- 方案 C：把 `generate_sql.prompt` 改坏，触发生成/校验问题，定位到智能体层。

**学生分步骤**：
1. 现象：界面/curl 报什么错、卡在哪一步。
2. 按 debug 分层表自底向上排查，定位到具体层。
3. 修复，验证恢复。
4. 写一段“故障定位报告”：现象→排查过程→根因→修复。
⚠ **预案**：演练后务必恢复环境（重启 embedding / build-kb / 还原 prompt）。

### 💻 任务衔接到大作业（学生开始动手）
鼓励完成演练快的同学，直接开始搭自己课程设计方向的脚手架。

## 五、课程设计大作业发动 + 选题指导（40 min）

⏱ 1:10–1:50

🗣 **发动（5 min）**：
- “从第 1 讲起，每讲的‘挑战级’练习都在为今天铺垫。现在把它做成一个完整的小工程——**在掌柜问数上做一项可演示的功能增强**。”

🗣 **逐方向点评（20 min）**：把 5 个方向过一遍，每个讲“改哪层、关联哪讲、验收看什么、常见坑”。

✍ **板书（选题方向表）**：
```
方向            改动层              关联讲       验收要点
①结果可视化     前端                第8/9        按结果自动选图(柱/折线/饼),维度度量映射合理
②多轮对话       State+API+召回/生成  第6/8        上下文追问("那华东呢?"),会话隔离
③SQL安全护栏    新增校验节点         第7          只读/防多语句/强制LIMIT,拦截危险SQL
④召回评测       评测脚本             第5          金标准集+Recall@K+≥2改进对比
⑤知识库扩域     dw建表+meta配置      第4          接入新主题,能问≥5个有意义问题
```
🗣 选题建议：“选**你前面挑战题已经起过步**的方向，事半功倍。难度上：④⑤偏数据/知识库（适合喜欢数仓的同学），①偏前端，②③偏后端工程。”

🗣 **讲评分（10 min，对照教师手册）**：
```
代码20% + 报告10% + 答辩10%
加分: 效果可量化/考虑边界异常/工程规范/有创新
扣分: 直接执行未约束SQL(除非做安全)/密钥入库/改坏原链路/报告与代码不符
报告参照 docs/04-设计文档.md 风格: 需求→方案→关键实现→测试效果→不足
```

🗣 **答辩形式（5 min）**：“5 分钟演示 + 三问：**是什么、为什么这么做、还能怎么改进**。重点不是功能多炫，而是你**理解不理解自己改的那层、讲不讲得清设计权衡**。”

## 六、结语（5 min）

⏱ 1:50–1:55

🗣 **讲稿（升华，对接“能动性”主线）**：
> “这门课最想留给你们的，不是‘会跑掌柜问数’，而是**理解它每一处设计的取舍**——为什么要知识库、为什么召回求全过滤求准、为什么校验后还要纠错、为什么 session 不能共享。这些‘为什么’，比任何一行代码都值钱。
>
> 掌柜问数不是一个跑通就结束的 Demo，而是一套能不断生长的工程骨架。把课程设计当成一次真实的小工程，去发挥你的能动性，长出**属于你自己的、更优秀的增强**。这，才是这门课真正的结课作品。”

✍ **板书（最终定格）**：
```
这门课的收获:
  不是"会跑", 而是理解每处设计的"为什么"
  掌柜问数 = 可生长的工程骨架
  发挥能动性 → 创造你自己的增强
```

## 七、本讲常见问题预案

| 学生可能问 | 应对 |
| --- | --- |
| 前端为什么是 fronted | 项目目录拼写如此,提醒别打错;必须跑5173(CORS) |
| 不知道选哪个大作业方向 | 选前面挑战题起过步的;按兴趣(数据/前端/后端)引导 |
| 大作业要做得很大吗 | 不必;重在理解所改之处+讲清权衡+效果可量化 |
| 故障演练定位不到 | 严格按自底向上分层表走,别跳层 |
| 报告不会写 | 参照 docs/04-设计文档.md 结构 |

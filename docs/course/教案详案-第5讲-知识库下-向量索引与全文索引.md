## 一、本讲定位与教学法说明

- **性质**：知识库的“检索能力”一讲。给上讲的结构化元数据装上向量索引和全文索引。
- **核心矛盾**：学生可能没接触过向量检索，对“语义相似”没概念；也容易把“向量”和“全文”当成可互换的两种搜索。
- **必须钉死的认知**：
  1. **向量=语义相似，全文=关键词精确**，两者**互补**，分别用于字段/指标 vs 取值。
  2. **同一字段建多个 point（name/desc/每个 alias）**——多入口召回，提召回率。
  3. **`SYS_ISCLEAN_CONFIG=true` 会每次清空重建**——别误跑丢数据。
- **教学法**：先讲原理（用直觉解释向量），再读两个 repository，最后用**对照实验**亲手验证“为什么要两种检索”（回收第 1 讲思考题 3）。
- **总时长**：4 学时（理论约 85 分钟 + 上机约 95 分钟，上机含关键对照实验）。
- **前置**：第 4 讲已把结构化元数据写进 meta 库。

### 段落 1 · 两类检索：语义 vs 关键词（原理，16 min）

⏱ 0:06–0:22

> 钉死认知 1。向量检索是很多学生的盲区，用直觉讲清。

🗣 **讲向量检索（用直觉，别堆数学）**：
> “Embedding 把一段文本变成一串数字（向量），比如 1024 个数。**关键性质：意思相近的文本，向量在空间里距离也近。** ‘销售额’和‘营收’语义接近，它俩的向量就挨得近；‘销售额’和‘星期三’离得远。检索时，把用户的词也变成向量，找空间里最近的几个——这就是‘语义检索’。”

🗣 **讲全文检索（学生熟悉，快讲）**：
> “全文检索是传统搜索：分词 + 倒排索引，比的是‘**关键词字面匹配**’。‘华东’就找含‘华东’的。它不懂语义——你搜‘营收’它不会联想到‘销售额’。”

🗣 **讲互补（核心）**：
✍ **板书（对照表，重点）**：
```
            向量(Qdrant)          全文(ES)
原理        文本→向量,比距离       分词→倒排,比关键词
擅长        语义相近(营收≈销售额)  精确字面(取值"华东")
本项目用于  字段/指标召回          字段"取值"召回
失效        专名/精确值            同义/语义改写
```
🗣 **讲分工理由**：
> “**字段/指标用向量**——用户措辞千变万化，需要语义匹配。**取值用全文**——‘华东’就是‘华东’，要精确，而且取值量大（一个字段可能几万个值），全部向量化太贵。两者**互补**，覆盖不同召回需求。”

### 段落 2 · 向量索引：Embedding + Qdrant（18 min）

⏱ 0:22–0:40

🗣 **讲 Qdrant 数据模型**：
> “Qdrant 里：`collection` 像表；`point` 是一条数据 = id + vector(向量) + payload(原始数据)。”

🗣 打开 `backend/app/repositories/qdrant/column_qdrant_repository.py`，看两个方法：
```python
collection_name = 'data-agent-column'
async def ensure_collection(self):
    if not await self.client.collection_exists(self.collection_name):
        await self.client.create_collection(self.collection_name,
            vectors_config=VectorParams(size=app_config.qdrant.embedding_size,  # 1024
                                        distance=Distance.COSINE))               # 余弦相似度
async def search(self, embedding, score_threshold=0.6, limit=5) -> list[ColumnInfo]:
    result = await self.client.query_points(self.collection_name, query=embedding,
                                            score_threshold=score_threshold, limit=limit)
    return [ColumnInfo(**point.payload) for point in result.points]
```
🗣 四个讲点：
1. **`ensure_collection` 幂等**：不存在才建，可反复调用（呼应第 4 讲构建脚本可重跑）。
2. **`size=1024` + `COSINE`**：维度对齐 embedding 模型，用余弦相似度。
3. **`score_threshold=0.6`**：只要相似度≥0.6 的，滤噪；`limit=5`：每次 top-5，控候选规模。
4. **payload → ColumnInfo**：`ColumnInfo(**point.payload)` 直接反序列化成 entity。
   > “看，**第 4 讲说 entity 要‘可序列化’，回报在这儿**——存进去是 ColumnInfo，取出来还原成 ColumnInfo，无缝。”

✍ **板书（副板）**：
```
Qdrant: collection(表) / point(id+vector+payload)
ColumnQdrantRepository:
  ensure_collection(幂等, size=1024, COSINE)
  search(score_threshold=0.6过滤, limit=5) → payload还原成ColumnInfo entity
```

### 段落 3 · 多入口索引：name/desc/alias（12 min）

⏱ 0:40–0:52

> 钉死认知 2。这是召回率的工程保障，也是“别名为什么重要”的兑现。

🗣 **讲稿**：打开 `MetaKnowledgeService._save_column_info_to_qdrant`：
```python
for column_info in column_infos:
    points.append({"id": uuid4(), "embedding_text": column_info.name,        "payload": column_info})
    points.append({"id": uuid4(), "embedding_text": column_info.description, "payload": column_info})
    for alia in column_info.alias:
        points.append({"id": uuid4(), "embedding_text": alia,                "payload": column_info})
for i in range(0, len(embedding_texts), 10):   # 每批10条向量化
    batch_embeddings = await self.embedding_client.aembed_documents(embedding_texts[i:i+10])
```
🗣 **讲透“多入口”（核心）**：
> “看好这个设计：同一个字段，用它的**名称、描述、每个别名**分别生成一个 point，但 payload **都指向同一个 ColumnInfo**。这意味着——用户说‘大区’命中别名、说‘地区名称’命中描述、说‘region_name’命中名称，**任何一条路都能召回到这同一个字段**。这就是召回率的保障。”
🗣 回收第 4 讲：“现在懂为什么第 4 讲反复强调 alias 重要了吧——每个 alias 都是一条独立的召回入口。”
🗣 **批量 embedding**：“每批 10 条一起向量化，而不是逐条请求 TEI——省往返、提效率。”

🗣 一句话带过指标：“`_save_metric_info_to_qdrant` 同理，指标也是 name/desc/alias 多入口。”

✍ **板书（重点）**：
```
多入口索引: 同一字段 → name/description/每个alias 各建一个point
            payload都指向同一ColumnInfo
⇒ 用户说任何一种叫法都能召回到该字段(召回率保障)
批量embedding(每批10条)提效率
```

### 段落 4 · 全文索引：ES + IK（14 min）

⏱ 0:52–1:06

🗣 **讲稿**：打开 `backend/app/repositories/es/value_es_repository.py`：
```python
index_name = 'data-agent-value'
index_mappings = {
    "dynamic": False,
    "properties": {
        "id":        {"type": "keyword"},
        "value":     {"type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_max_word"},
        "column_id": {"type": "keyword"}
    }
}
async def search(self, keyword, score_threshold=0.6, limit=5) -> list[ValueInfo]:
    result = await self.client.search(index=self.index_name, query={"match": {"value": keyword}},
                                      min_score=score_threshold, size=limit)
    return [ValueInfo(**hit['_source']) for hit in result['hits']['hits']]
```
🗣 三个讲点：
1. **`value` 用 `ik_max_word`**（第 2 讲装的 IK）：中文最细粒度分词，才能正确匹配；`id`/`column_id` 用 `keyword`（不分词、精确）。
2. **`match` + `min_score`**：关键词匹配，top-5。
3. **`column_id` 关联回字段**：“召回到取值‘华东’，靠 `column_id` 知道它属于 `dim_region.region_name`。”

🗣 **哪些取值进 ES——sync 决定**（回收第 4 讲）：看 `_save_value_info_to_es`：
```python
column2sync = {f"{t.name}.{c.name}": c.sync for t in meta_config.tables for c in t.columns}
for column_info in column_infos:
    if column2sync[column_info.id]:        # 只同步 sync=true 的列
        values = await self.dw_mysql_repository.get_column_values(table, column, 100000)
        ...
```
> “只有 `sync: true` 的列，取值才灌进 ES。这就是第 4 讲那个 sync 字段的兑现。”

✍ **板书（副板）**：
```
ES全文: value字段用 ik_max_word(中文分词), id/column_id用keyword(精确)
        match查询 + min_score; column_id关联回字段
进ES的取值由 sync=true 决定(第4讲的兑现)
```

### 段落 5 · build 总编排 + 清空副作用 + 小结（14 min）

⏱ 1:06–1:20

🗣 **build 总编排**：`MetaKnowledgeService.build()` 把全流程串起来：
```
加载配置 → 处理表(写meta库 + 字段向量索引 + 取值全文索引) → 处理指标(写meta库 + 指标向量索引)
```
入口 `build_meta_knowledge.py` 负责初始化客户端、解析 `--conf/--clean`。

🗣 **清空副作用（钉死认知 3，必须强调）**：
> “`.env` 里 `SYS_ISCLEAN_CONFIG=true`，意味着**每次**跑 build 脚本都会先 `clean()`：删 meta 四表、删 Qdrant 两个 collection、删 ES 索引，再重建。”
🗣 看 `clean()` 的删除顺序：“注意**先删子表 column_metric 再删父表**——遵守外键约束。这是个细节，但删错顺序会报外键错误。”
⚠ **警示**：“反复跑 build-kb = 反复清空重建。**别在你刚扩了知识库之后又误跑**，否则白扩。生产环境要把它设 false 做增量。”

🗣 **小结三句**：
1. 向量=语义、全文=关键词，互补。
2. 多入口索引（name/desc/alias）保召回率。
3. build 每次清空重建，小心 `SYS_ISCLEAN_CONFIG`。

❓ 留作上机：“用对照实验亲手验证——向量擅长‘营收→order_amount’，全文擅长‘华东→取值’。”

### 💻 上机任务 3：对照实验（45 min，核心，回答第 1 讲思考题 3）
> 让学生**亲手**感受两种检索的擅长与失效。

**实验 A：向量擅长语义**
- 用 embedding 把“营收”向量化 → Qdrant 检索，看能否召回 `order_amount`（语义匹配，字面完全不同也能中）。

**实验 B：全文擅长精确**
- 用 ES 检索“华东” → 看能否召回 `dim_region.region_name` 的取值（精确匹配）。

**实验 C：交叉失效（关键，让学生看到“为什么不能只用一种”）**
- 用 ES 检索“营收”——大概率召回不到 order_amount（全文不懂语义）。
- 用向量检索“华东”这种精确取值——效果不如 ES 精准。

## 四、原理精讲

### 4.1 配置管理：YAML × dataclass × OmegaConf

配置与代码分离是工程铁律。本项目用 OmegaConf 把 `backend/conf/app_config.yaml` 加载成**强类型** dataclass 对象。

看 `backend/app/conf/app_config.py`：

```python
@dataclass
class DBConfig:
    host: str
    port: int
    user: str
    password: str
    database: str

@dataclass
class AppConfig:
    logging: LoggingConfig
    db_meta: DBConfig
    db_dw: DBConfig
    qdrant: QdrantConfig
    embedding: EmbeddingConfig
    es: ESConfig
    llm: LLMConfig

config_file = Path(__file__).parents[2] / 'conf' / 'app_config.yaml'
context = OmegaConf.load(config_file)                          # 读 YAML
schema = OmegaConf.structured(AppConfig)                       # 用 dataclass 当 schema
app_config: AppConfig = OmegaConf.to_object(OmegaConf.merge(schema, context))  # 合并并校验类型
```

精读要点：
- `OmegaConf.structured(AppConfig)`：把 dataclass 变成带类型约束的 schema。
- `OmegaConf.merge(schema, context)`：用 YAML 的值填充 schema，**类型不符会报错**——这就是“结构化配置”的价值：配置写错（比如 port 写成字符串）在启动时就暴露，而不是运行到一半才崩。
- `app_config` 是**模块级单例**，全项目 `from ... import app_config` 直接用。

> ⚠️ 安全提醒：`app_config.yaml` 里含 LLM 的 `api_key` 和数据库密码。真实项目中应从环境变量/密钥管理读取，**绝不入库**。本教学项目为方便直接写在文件里，学生要养成“密钥不进 Git”的意识。

`meta_config.py` 同理，是知识库配置的 schema（第 4 讲详讲）。

### 4.2 项目根目录的动态定位

很多路径要相对“项目根”计算。看 `backend/app/constants/project_constant.py`：

```python
def _find_project_root(identifier: str = ".env") -> Path:
    env_root = os.getenv("PROJECT_ROOT")          # 1. 优先读环境变量（生产/Docker）
    if env_root and Path(env_root).absolute().exists():
        return Path(env_root).absolute()
    current_dir = Path(__file__).absolute().parent  # 2. 否则向上递归找 .env（开发）
    while current_dir != current_dir.parent:
        if (current_dir / identifier).exists():
            load_dotenv(dotenv_path=current_dir / identifier)
            return current_dir
        current_dir = current_dir.parent
    raise FileNotFoundError(...)
```

“环境变量优先、否则向上找标识文件”是一种**兼容开发与部署**的通用技巧。`Makefile` 启动容器时会注入 `PROJECT_ROOT`。

### 4.3 日志：配置驱动 + 位置精准 + request_id

看 `backend/app/conf/logger.py`，基于 loguru，重点理解三件事：

1. **配置驱动**：通过 `.env` 控制控制台/文件开关、级别、保留天数。
2. **双输出**：控制台彩色 + 文件 `logs/app_YYYYMMDD.log`（按天 rotation）。
3. **位置精准**：`fix_log_position` 遍历调用栈，跳过 loguru 内部帧和 logger.py 自身，定位到**真正的业务调用位置**——否则日志里全显示 logger.py 的行号，没法 debug。

```python
LOG_FORMAT = (
    "<green>{time:YYYY-MM-DD HH:mm:ss.SSS}</green> | "
    "<level>{level: <8}</level> | "
    "<cyan>{name: <20}</cyan>:<cyan>{function: <15}</cyan>:<cyan>{line: <4}</cyan> - "
    "<level>{message}</level>"
)
```

全项目 `from backend.app.conf.logger import logger` 直接用，开箱即用。

### 4.4 客户端管理器：统一的 init/close 模式

四个中间件各有一个“客户端管理器”，模式高度统一：`__init__` 存配置，`init()` 建连接，`close()` 释放。

**Embedding**（`backend/app/clients/embedding_client_manager.py`）：
```python
class EmbeddingClientManager:
    def __init__(self, config: EmbeddingConfig):
        self.client = None
        self.config = config
    def _get_url(self):
        return f"http://{self.config.host}:{self.config.port}"
    def init(self):
        self.client = HuggingFaceEndpointEmbeddings(model=self._get_url())
embedding_client_manager = EmbeddingClientManager(app_config.embedding)  # 模块级单例
```

**Qdrant / ES**（`qdrant_client_manager.py` / `es_client_manager.py`）：同样 `init()` 建异步客户端，`close()` 释放。

**MySQL**（`backend/app/clients/mysql_client_manager.py`）最值得精读，它涉及连接池和 session 工厂：
```python
class MysqlClientManager:
    def _get_url(self):
        return f"mysql+asyncmy://{user}:{password}@{host}:{port}/{database}?charset=utf8mb4"
    def init(self):
        self.engine = create_async_engine(url=self._get_url(),
                                          pool_size=10, pool_pre_ping=True)   # 连接池
        self.session_factory = async_sessionmaker(self.engine,
                                                  autoflush=True,
                                                  expire_on_commit=False,
                                                  autobegin=True)

dw_mysql_client_manager = MysqlClientManager(app_config.db_dw)     # 两个库两个管理器
meta_mysql_client_manager = MysqlClientManager(app_config.db_meta)
```

精读要点：
- `mysql+asyncmy://`：异步驱动（`asyncmy`），配合 `async/await` 实现高并发。
- `pool_size=10`：连接池，复用连接、控制并发。
- `pool_pre_ping=True`：取连接前先 ping，避免拿到已失效的连接。
- **engine（连接池）单例长存，session 每次用 `session_factory()` 新建**——这是第 4.5 节的关键。

### 4.5 为什么“引擎单例、session 每请求”

- **引擎/连接池**：建立成本高（TCP、握手），应在应用启动时建一次、全程复用 → 单例 + `init/close`。
- **session（会话）**：代表“一次工作单元/一个事务上下文”，应短生命周期、每个请求新建用完即弃 → `session_factory()` 配合 `async with`。

混用会出事：多个请求共享一个 session 会导致事务串扰、状态污染。第 8 讲会看到 FastAPI 如何用 `Depends` 为每个请求注入一个新 session。

### 4.6 分层架构与依赖方向

```
api(路由/schema/依赖)  →  services(业务编排)  →  agent(智能体节点)
                                                      ↓
                              repositories(数据读写)  →  clients(连接管理)
```

- `entities/`：领域对象（dataclass，作为 Qdrant/ES 的 payload）。
- `models/`：SQLAlchemy ORM 模型（仅 `meta` 库）。
- `repositories/`：封装数据读写（隔离 SQL/检索细节）。
- 依赖**单向向下**，上层依赖下层抽象，不反向。这让每层可独立测试、替换。

## 六、常见坑

- 直接 `python backend/app/conf/app_config.py` 会因绝对导入 `backend.app.*` 失败 → 必须 `python -m backend.app.conf.app_config`。
- `expire_on_commit=False` 的作用：commit 后对象属性仍可访问（否则惰性加载会触发新查询甚至报错）。
- 异步代码里忘了 `await` 是最常见 bug，表现为拿到一个 coroutine 而不是结果。

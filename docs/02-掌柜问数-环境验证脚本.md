# 掌柜问数 — 环境验证脚本

> 以下脚本用于在 `make middleware` 启动后，逐项验证中间件、模型 API 和应用是否就绪。

## 1. 中间件验证

### 1.1 Embedding 服务（TEI）

```sh
curl -sS http://localhost:8081/embed \
  -X POST \
  -H "Content-Type: application/json" \
  -d '{"inputs":["测试"]}' | head -c 200
```

返回应为 1024 维浮点数数组（截断显示前 200 字节即可）。

### 1.2 MySQL

```sh
# 业务用户（推荐，后端实际使用的账号），通过 TCP 协议连接
mysql -h 127.0.0.1 -P 3306 -u storekeeper -p'178121' --protocol=TCP \
  -e "SHOW DATABASES;"

# 仅当需要做容器内运维（重建库/授权等）时再用 root
# mysql -h 127.0.0.1 -P 3306 -u root -p'178121' --protocol=TCP -e "SHOW DATABASES;"
```

> 真实部署环境请把密码替换为你自己的密码；密码包含特殊字符时建议用单引号包裹。
> `storekeeper` 账号由 `docker/.env.debug` 中的 `MYSQL_USER` / `MYSQL_PASSWORD` 定义，并在 `scripts/mysql/init/01-create-databases.sql` 中被授予 `dw` 和 `meta` 两库的全部权限；`backend/conf/app_config.yaml` 中的 `db_meta` / `db_dw` 也使用该账号。
> 如果 `docker/.env.debug` 中的 `MYSQL_PORT` 改成了 `3307`，上面命令的 `-P 3306` 也要同步改为 `-P 3307`。

### 1.3 Elasticsearch

```sh
# 集群健康
curl -sS http://localhost:9200/_cluster/health?pretty

# 验证 IK 分词器（compose 启动时会自动安装 analysis-ik 8.19.10）
curl -sS -X POST "http://localhost:9200/_analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "analyzer": "ik_max_word",
    "text": "尚硅谷掌柜问数"
  }'
```

### 1.4 Qdrant

```sh
curl -sS http://localhost:6333/healthz
# 返回: healthz check passed
```

### 1.5 Kibana Data View 初始化

如果 Kibana 的 Discover 页面默认停留在 `All logs`，会使用 `logs-*` 索引模式，因此看不到本项目写入 ES 的 `data-agent-value` 数据。先确认 ES 中已有数据，再创建 Kibana Data View：

```sh
# 确认 ES 索引里已有字段取值数据
curl -sS http://127.0.0.1:9200/data-agent-value/_count

# 创建 Kibana Data View
curl -sS -X POST 'http://127.0.0.1:5601/api/data_views/data_view' \
  -H 'kbn-xsrf: true' \
  -H 'Content-Type: application/json' \
  -d '{"data_view":{"title":"data-agent-value","name":"data-agent-value"}}'
```

创建完成后打开 Kibana：<http://127.0.0.1:5601>，进入 `Discover`，选择 `data-agent-value`，应能看到字段取值文档。示例数据集通常有 75 条，主要字段包括 `id`、`column_id`、`value`。

## 2. 大模型（Chat）API 验证

`backend/conf/app_config.yaml` 中默认配置了智谱 GLM 接口：

```yaml
llm:
  model_name: glm-5.1
  api_key: <你的 API Key>
  base_url: https://open.bigmodel.cn/api/paas/v4
```

验证脚本（请把 `model` 和 `Authorization` 替换为你自己账号中可用的模型名与 API Key）：

```sh
curl -sS --location 'https://open.bigmodel.cn/api/paas/v4/chat/completions' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "<your-model-name>",
    "messages": [
      {"role": "user", "content": "你好"}
    ]
  }'
```

> 仓库样例中的 API Key 仅用于演示，请勿在生产环境直接使用。如果智谱平台没有你配置的 `model_name`，请到 [BigModel 控制台](https://open.bigmodel.cn/) 查看你账号下可用的模型并同步更新 `app_config.yaml`。

## 3. 应用端到端验证

确认中间件和后端都已启动后：

1. 浏览器打开 <http://127.0.0.1:5173/>
2. 输入示例查询：
   ```
   统计一下各个地区销售排行前三的产品
   ```
3. 观察前端是否流式输出节点进度（抽取关键字 → 召回字段/值/指标 → 合并 → 过滤 → 生成 SQL → 校验/校正 → 执行）并给出结果表。

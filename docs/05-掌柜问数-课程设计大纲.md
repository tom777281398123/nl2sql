# 掌柜问数 — 课程设计总体大纲

> 本大纲将《尚硅谷大模型项目之掌柜问数》开发笔记教学化，面向 **大数据专业大四学生**，
> 作为一门项目实训 / 课程设计课。对应代码仓库 `storekeeper-nl2sql`，对应笔记
> `1.笔记/尚硅谷大模型项目之掌柜问数.md`。
>
> 本文件只是**总体大纲**（课时表 + 每讲概要 + 实验/作业/考核框架）。
> 是否把每一讲展开成完整教案，待大纲确认后再决定。

## 一、课程定位与先修

### 1.1 课程性质
- 类型：项目实训 / 综合课程设计（理论 30% + 实践 70%）
- 学分建议：2–3 学分，**32–40 学时**（含上机）
- 形态：以一个可运行的工业级 NL2SQL 系统为主线，边讲边做，最终人人能跑通并能改造。

### 1.2 教学对象与先修
教学对象为大数据专业大四学生，默认已具备：

| 已具备（先修） | 本课程负责补齐 |
| --- | --- |
| SQL、关系数据库、数据仓库基本概念（维度建模、星型模型） | 元数据知识库的工程化组织 |
| Python 基础、面向对象 | 异步编程 `async/await`、依赖注入、分层架构 |
| 了解机器学习/NLP 基本概念 | 向量检索、Embedding、全文检索、LLM 应用编排 |
| Linux/命令行、Git 基础 | Docker Compose 编排中间件、服务化部署 |

> 大数据专业学生对“数仓/星型模型/SQL”有天然优势，本课程的**增量价值**在于：把他们熟悉的数仓，接上大模型，做成“自然语言问数”系统。教学重心应落在 **检索增强 + LLM 编排 + 工程落地**，数仓部分可快讲。

### 1.3 总体能力目标
学完本课程，学生应能够：
1. 说清 NL2SQL 系统的整体架构与“为什么这样设计”（可控性、准确性来源）。
2. 独立搭建 MySQL + Elasticsearch + Qdrant + Embedding + LLM 的开发环境。
3. 理解并能扩展“元数据知识库”的三类索引（结构化/向量/全文）。
4. 读懂并能改造一个基于 LangGraph 的多节点智能体工作流。
5. 实现流式（SSE）前后端联调，交付一个可演示的问数应用。
6. 具备工程素养：分层、配置管理、日志、依赖注入、异步、容器化。

## 二、项目全景（一页纸心智模型）

```
用户自然语言
   │
   ▼
[抽取关键字] ──► [多路召回] 字段(向量) / 取值(全文) / 指标(向量)
   │                         │
   │                         ▼
   │                   [合并召回信息]
   │                         │
   │              ┌──────────┴──────────┐
   │              ▼                     ▼
   │        [过滤表格]              [过滤指标]
   │              └──────────┬──────────┘
   │                         ▼
   │                  [补充上下文(日期/方言)]
   │                         ▼
   │                    [生成 SQL] ──► [校验 SQL] ──(错)──► [纠错 SQL]
   │                                        │(对)              │
   │                                        ▼◄────────────────┘
   │                                   [执行 SQL] ──► 结果表
   ▼
        全程 SSE 流式回传执行进度 + 结果
```

三大支柱：
- **元数据知识库**：MySQL（结构化元数据）+ Qdrant（语义向量索引）+ ES（取值全文索引）。
- **问数智能体**：LangGraph 编排 12 个节点，含并行召回与“校验→纠错”条件分支。
- **服务化**：FastAPI + SSE 流式接口 + Vue 前端。

## 四、每讲详细概要

### 第 1 讲：项目概述与系统架构
- **学习目标**：理解掌柜问数解决什么问题、整体架构、为什么用“知识库 + LLM”而不是“直接喂表结构给 LLM”。
- **重点**：数仓与业务库的区别；星型模型回顾（dim_* + fact_order）；NL2SQL 的准确性/可控性从哪来（检索增强 + 校验纠错）。
- **难点**：建立“多路召回 → 生成 → 校验”的整体心智模型。
- **上机**：阅读 `backend/conf/meta_config.yaml` 与 `scripts/mysql/init/*.sql`，画出本项目的星型模型 ER 图。
- **思政/职业素养点**：让业务“人人可问数”，数据民主化的价值。

### 第 2 讲：开发环境与中间件编排
- **学习目标**：掌握用 Docker Compose 一键拉起 MySQL/ES/Qdrant/Embedding。
- **重点**：`Makefile` + `docker/docker-compose-debug.yml` 解析；各服务职责（笔记 3.3.1）；`run.sh` 起停脚本用法。
- **难点**：Embedding（TEI）**离线加载本地模型**（见 `CLAUDE.md`）；ES 的 IK 分词器安装；端口冲突排查。
- **上机**：`./run.sh start` → 用 `docs/02-环境验证脚本.md` 逐项验证（embed 返回 1024 维、ES 集群健康、Qdrant healthz、LLM API 联通）。
- **常见坑清单**：3306 被本机 MySQL 占用、HuggingFace 下载超时、Docker 未启动。

### 第 3 讲：工程基础设施
- **学习目标**：理解一个工业级 Python 服务的“地基”。
- **重点**：OmegaConf 配置加载（`app_config`/`meta_config`）；loguru 日志 + request_id 注入；四类客户端管理器（MySQL/Embedding/Qdrant/ES）的 `init/close` 生命周期。
- **难点**：异步 SQLAlchemy（`asyncmy`、`async_sessionmaker`）；为什么用 client manager 单例 + 每请求 session。
- **上机**：分别运行各 `*_client_manager.py` 的 `__main__` 自测块，连通三个存储。
- **工程素养点**：分层（api/services/agent/repositories/clients）、配置与代码分离、密钥管理（提示 `app_config.yaml` 含密钥，不应入库）。

### 第 4 讲：元数据知识库（上）——建模与结构化元数据
- **学习目标**：把数仓 schema/指标，组织成 LLM 可消费的“知识”。
- **重点**：`entities` 领域对象 vs `models` ORM vs `mappers` 转换；`meta` 库四张表（table_info/column_info/metric_info/column_metric）；`meta_config.yaml` 的 role / alias / sync 字段语义。
- **难点**：为什么要 alias（别名召回）；sync 控制哪些列的取值进全文索引。
- **上机**：给 `meta_config.yaml` 新增一张维度表/一个指标，跑通写入 `meta` 库（暂不建索引）。

### 第 5 讲：元数据知识库（下）——向量索引与全文索引
- **学习目标**：理解“语义检索 + 全文检索”双通道，并能构建。
- **重点**：Embedding 把 name/description/alias 向量化写入 Qdrant；字段取值写入 ES（IK 分词）；`MetaKnowledgeService.build()` 全流程。
- **难点**：批量 embedding；collection/index 的 ensure 与清空（`SYS_ISCLEAN_CONFIG` 的副作用）。
- **上机**：`./run.sh build-kb`，在 Qdrant/ES 中验证数据已写入；对比“向量召回”和“全文召回”各自擅长的查询。

### 第 6 讲：问数智能体（上）——召回与过滤
- **学习目标**：读懂 LangGraph 的 State/Context/Node 模型，掌握前 8 个节点。
- **重点**：`DataAgentState`(TypedDict) 与 `DataAgentContext`(依赖注入袋)；`extract_keywords`(jieba)、三路并行 `recall_*`、`merge_retrieved_info`、`filter_table/filter_metric`（LLM 过滤）。
- **难点**：图的并行 fan-out / fan-in；节点用 `runtime.context[...]` 取依赖而非 import；用 LLM 做“相关性过滤”的提示词设计。
- **上机**：单独跑召回节点，观察对同一问题三路各召回了什么；改一个 prompt 看过滤效果变化。

### 第 7 讲：问数智能体（下）——生成-校验-纠错-执行
- **学习目标**：掌握 SQL 生成闭环与“自我纠错”机制。
- **重点**：`add_extra_context`（注入日期/方言）、`generate_sql`、`validate_sql`、**条件边**（error 为空→执行，否则→纠错）、`correct_sql`、`execute_sql`；SSE 进度事件协议（progress/result/error）。
- **难点**：条件边的写法与状态驱动；校验如何捕获错误并喂回 LLM 纠错。
- **上机**：运行 `graph.py` 的 `__main__`，命令行端到端出结果；构造一个会触发纠错分支的查询。

### 第 8 讲：API 服务化与流式接口
- **学习目标**：把智能体包装成可被前端调用的流式服务。
- **重点**：FastAPI `lifespan` 初始化/释放长连接客户端；`Depends` 依赖链构建 `QueryService`；`StreamingResponse` + SSE（`text/event-stream`）；中间件注入 request_id；CORS。
- **难点**：SSE 数据格式 `data: {...}\n\n`；异步生成器 `astream` 转发。
- **上机**：用 `curl -N` 打 `/api/query` 观察流式输出；看 `/docs` 调试。

### 第 9 讲：前后端联调、答辩与拓展
- **学习目标**：完成完整闭环并交付。
- **重点**：启动 Vue 前端（`fronted/`，注意拼写）；CORS 白名单 5173；浏览器端到端演示。
- **拓展讨论（为课程设计选题铺垫，不强制实现）**：结果可视化（图表）、多轮对话、SQL 安全（只读/防注入）、召回质量评测、更多表/指标、知识库增量更新。
- **课程设计验收**：见第六节。

## 六、课程设计大作业（综合验收）

**任务**：在掌柜问数基础上，完成一项“可演示的功能增强”，并撰写报告 + 答辩。

学生从下列方向**任选其一**（或自拟，需教师批准）：
1. **结果可视化**：前端根据结果数据自动选图（柱/折线/饼）。
2. **多轮对话**：支持上下文追问（“那华东呢？”）。
3. **SQL 安全护栏**：限制为只读、拦截危险语句、加超时与行数限制。
4. **召回评测**：构造 20 条问题的金标准，量化召回准确率并提出改进。
5. **知识库扩域**：接入一套新的数仓主题（新增多表多指标）并问数。

**交付物**：
- 可运行代码（在原仓库分支上）。
- 设计报告（参照 `docs/04-设计文档.md` 风格）：需求、方案、关键实现、测试、不足。
- 5 分钟现场演示 + 答辩。

## 九、教学建议（讲好这门课的几个要点）

1. **先跑通，再拆解**：第 2 讲就让学生看到完整效果（浏览器问一句出结果），建立成就感与全局观，再回头逐层讲实现。
2. **用大数据学生的“数仓优势”切入**：从他们熟悉的星型模型讲起，自然过渡到“给数仓装上自然语言入口”。
3. **把“为什么”讲透**：每个设计点都问一句“不这样行不行”——例如为什么要知识库、为什么要校验纠错、为什么向量+全文双通道。
4. **善用对照实验**：向量召回 vs 全文召回、改 prompt 前后、触发纠错分支，让学生在差异中理解机制。
5. **强调工程素养**：分层、配置/日志/异步/容器化，是大四学生走向职场最需要补的部分，比“调通模型”更长期受益。
